## Architecture and public boundary

The package is a compound React row API. `Root` owns gesture state,
measurements, direction normalization, focus, and direct DOM motion. `Content`
is the translated foreground. Measured `Leading` and `Trailing` containers sit
behind it, and native-button `Action` components register their widths and
optional full-swipe eligibility. `Group` coordinates only row disclosure;
application data, effects, removal, undo, confirmation, async state, and
virtualization remain consumer-owned.

The public API remains the 16 design-approved exports:

- Runtime: `Action`, `Content`, `Group`, `Leading`, `Root`, `SwipeActions`, and
  `Trailing`.
- Types: `SwipeActionsActionProps`, `SwipeActionsContentProps`,
  `SwipeActionsDirection`, `SwipeActionsGroupProps`, `SwipeActionsHandle`,
  `SwipeActionsOpenSide`, `SwipeActionsRootProps`, `SwipeActionsSide`, and
  `SwipeActionsSideProps`.
- Package subpaths: `.`, `./core.css`, `./theme.css`, `./styles.css`, and
  `./package.json` only.

The distribution supplies externalized ESM and CommonJS and one bundled
`dist/index.d.ts`. No private component, gesture, motion, state, or utility
declaration files ship. React and React DOM remain peer dependencies; the
package has zero runtime dependencies. The declaration bundler is development
tooling only.

## Final interaction and runtime behavior

- Intent stays pending inside the 6 px radial dead zone. Beyond it, a 1.2×
  dominant axis wins immediately. Near-diagonal movement stays pending until an
  axis becomes decisive or radial movement reaches the explicit 18 px decision
  boundary, where the deterministic tie rule gives ownership to vertical
  scrolling.
- Velocity uses recent samples from a 100 ms window, is clamped to ±2 px/ms,
  and projects 120 ms. Opening uses 0.35 of measured side width by default.
- Full swipe uses 0.7 of row width by default. Velocity-assisted activation
  requires at least 15% of row width in signed directional pointer displacement.
  An existing default-open offset is tracked separately and cannot satisfy that
  safety gate. LTR and RTL tests prove a 13 px extension does not invoke, while
  a genuine 48 px extension may invoke on a 320 px row.
- Full-swipe arming has a three-percentage-point internal hysteresis band,
  bounded by the normal open threshold. Visual arming and release resolution
  share the same boundary, preventing threshold chatter or semantic mismatch.
- Crossing closed from a gesture that began open applies a bounded opposite-side
  gate: the smaller of 25% of the resting side width and 15% of row width. Pure
  resistance coverage exercises both starting sides in LTR and RTL.
- Group ownership commits at the release decision for an opening drag, before
  the successor settles. The previous row stays open during drag, closes as
  settling begins, and receives one close request. Controlled successors close
  the previous peer at the same boundary, request their new side once at settle,
  and still reconcile to the controlled prop.
- Starting a new settle captures the currently visible coordinate. The canceled
  promise resolves `{ status: 'canceled' }`; the replacement begins at that
  coordinate and resolves `{ status: 'completed' }` at its target.
- `theme.css` no longer transitions content transforms. The parsed CSS policy
  rejects both `transition` and `transition-property` values containing
  `transform` or `all`. A browser fixture imports the combined `styles.css` and
  proves computed transform follows the direct JavaScript-written coordinate.
- Browser-sensitive layout work uses an isomorphic layout effect: server render
  selects the passive effect, while client bundles preserve layout-effect
  timing. Packed React 18 and 19 fixtures render a default-open logical side,
  hydrate it, assert stable open state and focusability, assert no recoverable
  errors, and require empty process stderr.
- `Content`, `Leading`, and `Trailing` now emit actionable, globally deduplicated
  development warnings when rendered outside `Root`.

## Known limitations and manual checks

- No physical Mobile Safari or Chrome Android device was available. Browser
  back-edge navigation ownership was not tested and is not inferred from
  desktop automation.
- No real third-party Bottom Sheet integration was run. Automated dialog and
  sheet-like containment does not establish compatibility with a particular
  library version, handle, snap point, or gesture configuration.
- Native continuous-touch vertical competition was automated only in Chromium;
  Firefox and WebKit use synthetic touch fallback for swipe coverage and skip
  that trusted-touch case.
- Actual Microsoft Edge, Chrome Android, Mobile Safari, assistive technology,
  and physical-device performance were not run locally.
- Nested swipe roots, portals, `asChild`, React Native, drag-and-drop ownership,
  automatic removal, undo, confirmation, async mutation state, and built-in
  virtualization remain unsupported or consumer-owned.
- Fully mounted list cost grows with rows and observed elements. Consumers own
  virtualization and must validate transformed layouts and custom scrollers.

These gaps and the need for real-world gesture/API feedback are why the release
remains `0.1.0-alpha.0`.
